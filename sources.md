(seed 20261016). Values were chosen by rule to fall clearly inside the pattern each case tests. The answer key is derived
by code from the printed reference range (flags) plus the cited thresholds below (interpretation and urgency).

## Considered and not used
- **Synthea** (Apache 2.0): generates longitudinal synthetic patients, but its lab values are not built to test specific traps (hemolysis, EDTA, unit swaps). Rule-based generation against cited thresholds gave a cleaner answer key. Synthea could add realistic background panels later.
- **MedQA** (MIT on GitHub) / **MedMCQA** (Apache 2.0): multiple-choice board questions, not lab reports with an urgency key. Converting them would mean re-writing answers, so they were skipped for v1.
- **Published case reports**: used only as pattern inspiration, no text copied.

## Who decided the urgency labels
The urgency tier for each category is the author's call, anchored to the critical-value list and guidelines above. These are the labels most worth a human check. See `data/answer_key.jsonl` field `urgency` and the table in README.

## Answer-key revision 2026-10-17
In physiologic-pregnancy cases, either flagging against the printed non-pregnant range or omitting the flag as pregnancy-normal is accepted, and the trap is judged on the interpretation. This rule was applied to all models after the frontier runs. See results.md.

## License compatibility
The repository's data (`data/`, `results/`, `figures/`) is released under CC BY 4.0 and the code under MIT (see `LICENSE-DATA`, `LICENSE`).
This is compatible with the sources above because no source text, tables, or figures are reproduced: the cases use numeric reference
ranges and clinical thresholds, which are facts, together with citations. Sources under CC BY-NC-ND (StatPearls) were read for
facts only; nothing from them is redistributed or adapted. The ABIM PDF and its text extraction (`sources/*.pdf`, `sources/abim.txt`)
are git-ignored and not redistributed; fetch the PDF from the URL above to audit the ranges.

When DeepSeek V4.1 Flash was added (2026-10-17), the interpretation keyword for the diabetes-range groups was widened from "diabetes" to the prefix "diabet" so that "diabetic range" is accepted. Cases are unchanged and no other model's scores changed. See results.md.
